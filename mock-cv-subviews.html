カスタムリスト・14本（見本）

この形の考え方

  • リスト … どの動画を入れるか（今までどおり。手で選ぶ／条件で作る）
  • 見え方（リストの中に何個でも・名前つき） … そのリストの動画をどう絞って、どうまとめて見せるか。Notion の「ビュー」と同じ
  • カード／テーブル … 今までどおりボタンでいつでも切り替え。見え方には含めない（どの見え方もカードでもテーブルでも見られる）

まとめ方は2種類

  • 今ある情報で（タグ・チャンネル・プレイリスト） … 絞り込みと同じ情報を、絞る代わりに列に分けて見せる。付け替えは動画のタグを変えること＝ライブラリ全体に効く
  • このリストの分け方で（自分で作る） … 「相手のポスチャー」「習熟度」など、名前も選択肢も自由。このリストの中だけの置き場所なので、動画のタグは変わらない。1つのリストに分け方をいくつでも作れて、どの見え方からでも使える

データの持ち方（案）

リストの中に2つ足すだけ。リストの動画（videoIds・条件）には触らない。
view.subViews = [{id, name, filter, groupBy, at}]（groupBy は {set:'分け方id'} か {tag:'グループid'}・'channel'・'playlist'・なし）
view.groupSets = [{id, name, options:[{id, name, color}], of:{動画id: 選択肢id}}]
  • 選択肢を消しても、そこにいた動画は「〇〇なし」の列に戻るだけ（リストからは消えない）
  • 分け方を消すときは本数を出して確かめ、直後に取り消せる。その分け方を使っていた見え方は「まとめない」に戻る
  • 見え方の絞り込みを変えると「変更あり」になり、上書き保存を押したときだけ覚える（v53.020 の条件リストと同じ決まり）。置き場所の付け替えはその場で保存（動画を動かした＝データを変えた、なので）
  • 端末をまたぐ同期は、今のリストの同期に乗る（1件ずつ・新しい方を採る）
  • 最初の見え方「すべて」は今の画面そのもの。何も作らなければ今と何も変わらない
